# 抖音直播数据：合规接入核对清单

本文只记录公开资料里能核对到的资质和路径，以及还没核实的空白。这里没有接口路径、签名算法、请求样例或采集步骤。本仓库的官方适配器是桩，不会发起平台网络请求。

资料来自抖音开放平台公开文档（访问日期以仓库提交时为准）。文档会改版，下面凡是写「待确认」的，都不能当成已经核准的能力。

## 官方公开能力与资质

这些页面是公开的产品说明，不是本项目实现过的接口。

- 账号与资质：[注册账户和资质认证](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/introduction/zn/jieruzhinan)。企业开发者需要提交营业执照等主体资质，并通过对公认证。个人开发者是另一套实名认证，不能默认覆盖企业直播能力。
- 入驻主体范围：[入驻开发者平台](https://developer.open-douyin.com/docs/resource/zh-CN/developer/join/join-into-developer-platform/)。主体包括企业、个体工商户、党政机关、事业单位、社会组织等，证照需要清晰，统一社会信用代码审核通过后通常不能改。
- 直播小玩法的创建与提案：[创建直播玩法](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/introduction/zn/toybox-start)。公开说明里，礼物、点赞、评论等互动数据要先创建玩法、通过提案评估，再在后台申请对应能力，并完成直播间数据的开发配置。具体字段和调用方式以控制台当前文档为准。待确认：未通过玩法提案的主体，是否还有别的公开通道可以拿到任意直播间的弹幕或礼物。
- 移动应用侧的直播 SDK：[抖音 SDK 接入流程](https://developer.open-douyin.com/docs/resource/zh-CN/dop/ability/douyin-live-sdk/introduction)。公开说明要求应用先上架，并给出 DAU 与《网络文化经营许可证》（经营范围含「网络表演」）一类门槛。这是 SDK 合作接入，不是本仓库可以代填的参数。
- 小程序类目里的「社交 / 直播」：[企业主体开放服务类目](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/operation/service-category/commercial-service-category)。该类目写明需要备案或增值电信许可，以及视听、网络文化经营许可证等材料中的一种，并且注明定向邀约。它约束的是小程序类目，不能直接当成直播间数据采集授权。

待确认（不要自行补全）：

- 直播玩法 OpenAPI 的当前路径、鉴权头、签名字段。以开放平台文档和正式应用凭证为准，本清单故意不抄。
- 抖音云或内网推送是否对所有入驻主体开放，还是只对已通过提案的玩法开放。
- 主播侧「房间授权」的法律文件和产品开关分别长什么样。

## 第三方合规服务：只做评估分类

不推荐、也不介绍任何具体采集器。评估时只看类别：

| 类别 | 要核对的东西 |
| --- | --- |
| 平台自己的玩法 / 云推送 | 是否出现在开放平台控制台，提案和能力申请是否通过，凭证是否发到你的主体名下 |
| 有书面授权的技术服务商 | 合同里的处理目的、房间范围、保存期限、分包和退出时的删除义务 |
| 号称能「直接看直播间弹幕」的非官方工具 | 默认视为未授权。没有平台或主播的书面授权，就不要接入 |

服务商评估可以问这几个问题：授权来自平台还是只来自口头承诺；数据是否出境；能否按房间删除；安全事件怎么通知你。不要向服务商索要绕过平台校验的方法。

## 自建非官方采集的风险

只说明风险，不说明做法。

- 合规：没有合法处理依据时，昵称、头像、评论内容都可能是个人信息。平台协议通常也不允许未授权抓取。
- 授权缺口：没有主播或平台对具体直播间的授权，后续无法向用户或监管说明数据从哪来。
- 稳定性：平台策略、客户端和风控会变，把演出系统绑在非官方采集上，直播中可能整段中断。
- 审计：非官方流量没有正式的应用编号和能力申请记录，出了问题对不上账。

本仓库不提供、也不接受这类采集的实现。

## 用户必须自行准备的材料

接入任何官方能力之前，由使用方准备并保管，不要放进这个仓库：

- 营业执照或同等主体证照，以及开放平台企业认证 / 对公认证通过的记录
- 开放平台应用的正式凭证（应用创建在使用方控制台，仓库只留环境变量名占位）
- 直播玩法提案通过、能力申请通过，或 SDK 合作审核通过的证明
- 针对具体直播间的授权（主播或机构同意采集、展示哪些字段）
- 处理这些数据的合法基础：同意、合同，或其他适用的法律规定
- 与服务商或共同处理者的数据处理协议，写明目的、期限、删除和安全责任
- 若使用官方 SDK：SDK 名称、版本，以及授权范围说明

`config/default.yaml` 里的 `adapters.official.contract` 和 `credential_env` 只是占位。空着表示还没有合同，也没有凭证环境变量。

## 可以走的合规路径

1. 继续用本仓库的 JSONL 回放和模拟源。这是默认路径，`REAL_SOURCE` 关闭时整条演示是完整的。
2. 资质和房间授权齐备之后，使用开放平台当前提供的官方能力或官方 SDK。实现必须由使用方按当时的正式文档接到自己的适配器里。本仓库的官方适配器在那之前保持桩：可以注册、可以报降级，不发起平台请求。
3. 使用方自己提供一个已经获授权的采集进程，向本仓库的适配器接口交付脱敏后的 `LiveEvent`（`start` / `stop` / `health` / `metrics` / `reconnect`）。接口只接收事件，不接收平台登录态。

没有上述材料时，保持模拟源。不要把「先抓下来再补手续」当成过渡方案。
