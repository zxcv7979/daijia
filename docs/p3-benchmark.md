# P3 画面基准

目标：10 倍事件流下，特效页不低于 55fps，绘制时间不高于 12ms，内存不无限增长。

这里的「10 倍」按样本回放大约每秒 2 条来估算，所以脚本用每秒 20 条模拟弹幕和礼物。事件仍走本地模拟接口，不连接平台。

## 怎么跑

先构建页面，再跑无头近似：

```bash
npm run build
python scripts/benchmark_overlay.py --seconds 12 --rate 20
```

脚本会自己起一个临时服务，用单独的 Chrome 配置打开 `http://127.0.0.1:8791/overlay/?preview=1&hud=1`。它量的是页面里上报的 FPS 和**绘制耗时**（一帧里 Three 和 Pixi 花的时间），不是 OBS 预览里的数字。

更长的内存观察可以把 `--seconds` 调到 180。云环境这次只跑了 12 秒。

## 这次无头 Chrome 的结果

环境没有独立显卡，Chrome 是 `--headless=new --disable-gpu`。绘制很快，但无头浏览器的 `requestAnimationFrame` 不稳定，所以 FPS 中位数不能当成实机成绩。

| 项目 | 结果 |
| --- | --- |
| 时长 / 注入速率 | 12 秒 / 20 条每秒 |
| FPS 中位数 / 最低 | 48 / 33 |
| 绘制耗时 p50 / p95 | 0.15 ms / 0.45 ms |
| 是否降档 | 否（绘制远低于 12ms 预算） |
| 粒子峰值 | 174（上限 20000） |
| 同时在场特效峰值 | 8（上限 8） |
| JS 堆首尾 | 9.1 MB → 9.5 MB |

绘制耗时低于 12ms。显示帧率受无头调度影响，没有稳定停在 55 以上。

## 待实机验收

真实 OBS 的 FPS、帧时间和数分钟内存还没有在这台机器上测。按 [obs-browser-source.md](obs-browser-source.md) 加 1920×1080、60fps 的透明浏览器源，管理页开 20x 回放或榜一剧本，看调试台：

- FPS 应不低于 55
- 绘制时间应不高于 12ms；若连续超预算，调试台应显示「已降档」，粒子变少并跳过次要特效
- 录 1 到 3 分钟，内存曲线不应一直往上
